# API 보안 체크리스트 (샘플 문서)

이 문서는 A2X 포탈 시연용 샘플이다. 실제 사내 표준이 아니다.

## 1. 등록 전 점검

외부 SaaS나 다른 회사 시스템과 연동하는 API는 등록 전에 정보보안팀의 보안 검토를 받는다.
API 키나 토큰을 URL 쿼리 파라미터로 받지 않는다. Authorization 헤더를 쓴다.
응답에 주민등록번호, 계좌번호, 전화번호 전체 같은 개인정보가 그대로 나가지 않는지 확인한다.

## 2. 호출 한도

API마다 호출 한도를 정하고, 한도를 넘으면 429를 돌려준다.
429가 반복되면 호출하는 쪽의 재시도 간격을 늘리고, 필요하면 대상 시스템 담당자에게 한도 상향을 요청한다.

## 3. 로그

호출 로그에는 사용자, 시스템, 시각, 결과 코드를 남긴다. 인증 정보와 개인정보는 가려서 저장한다.
오류 원인 분석을 위해 처리 단계별 소요시간을 함께 남긴다.

## 4. 외부 SaaS 연동

외부 SaaS 연동은 사내에서 외부로 나가는 방향만 허용하는 것이 원칙이다.
외부에서 사내로 들어오는 연동은 Gateway를 거치고 방화벽 신청을 따로 해야 한다.
