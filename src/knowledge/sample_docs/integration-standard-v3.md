# 사내 시스템 연계 표준 가이드 v3 (샘플 문서)

이 문서는 A2X 포탈 시연용 샘플이다. 실제 사내 표준이 아니다.

## 1. 연계 방식 선택 기준

AI Agent가 사내 시스템을 호출할 때는 API, MCP, A2A 세 가지 방식 중에서 고른다.
조회 위주의 Agent 연계는 MCP 방식을 권장한다. MCP는 Tool 단위로 권한을 나눌 수 있어 사용자별로 필요한 기능만 허용할 수 있다.
시스템 간 대량 데이터 전송이나 배치 연계는 API 방식을 쓴다. API 연계는 시스템 단위로만 사용 신청한다.
다른 팀의 Agent에게 업무를 통째로 맡길 때는 A2A 방식을 검토한다. A2A는 1차 범위가 아니며 Gateway 도입 후 지원한다.

## 2. 이미 API가 있는 경우

이미 운영 중인 API가 있으면 새로 MCP 서버를 개발하지 말고 A2X의 API → MCP 변환을 먼저 검토한다.
변환은 API 오퍼레이션 하나를 MCP Tool 하나로 바꾸며, 조회(GET) 오퍼레이션부터 공개하는 것을 권장한다.
데이터를 바꾸는 오퍼레이션(POST, PUT, DELETE)은 변경 Tool로 표시되고, 승인 시 업무 영향도를 함께 검토한다.
업무 로직이 복잡하거나 여러 API를 묶어야 하면 타겟 시스템에서 MCP 서버를 직접 개발해 MCP 등록으로 올린다.

## 3. 구독과 권한

모든 연계는 시스템 단위로 관리한다. AI Agent도 하나의 시스템으로 등록한다.
구독은 2단계다. 먼저 Agent 시스템이 대상 시스템의 MCP 서버 또는 API를 시스템 구독으로 신청하고, 대상 시스템 담당자가 승인한다.
연계가 성립한 뒤 개인 사용자가 MCP Tool별로 사용을 신청하고, 역시 대상 시스템 담당자가 승인한다.
시스템 구독을 해지하면 그 연계 안의 Tool 권한도 함께 해지된다.

## 4. 개인정보가 있는 API

개인정보가 포함된 API는 데이터 등급을 대외비로 등록하고 응답에서 개인정보를 마스킹한다.
개인정보 API를 MCP로 열 때는 조회 Tool만 공개하고, 검색 Tool은 결과 건수를 제한한다.
개인정보 API의 구독 승인 전에는 정보보안팀 검토를 받는다.

## 5. 등록 절차

API와 MCP 서버는 저장, 승인, 스테이지, 운영 순서로 진행한다.
시스템 담당자가 등록하고 승인 요청을 하면 admin이 승인하며, 스테이지에서 확인한 뒤 운영으로 전환한다.
운영 상태가 된 API와 MCP 서버만 카탈로그에서 구독할 수 있다.
