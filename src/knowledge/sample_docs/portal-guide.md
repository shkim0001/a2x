# A2X 포탈 사용 가이드 (샘플 문서)

이 문서는 A2X 포탈 시연용 샘플이다. 메뉴별로 무엇을 어떻게 하는지 안내한다.

## 1. 역할과 메뉴

따로 정하는 역할은 admin뿐이다. 누구나 카탈로그 조회, Tool 사용 신청, 내 권한, 내 호출 사용내역을 쓰고 새 시스템을 등록할 수 있다. 시스템을 등록하거나 어떤 시스템의 담당자로 추가되면 자동으로 시스템 담당자가 되어 그 시스템의 서버 · API · MCP 등록, 시스템 구독 신청, 담당 시스템으로 들어온 신청 승인 메뉴가 열린다. 담당 시스템이 모두 없어지면 다시 일반 사용자 화면이 된다. admin은 등록 승인, 운영 전환, 컨설팅 문서 관리를 한다.

상단 대메뉴는 홈, 기준정보(시스템 · 서버), 카탈로그 등록(API 등록 · MCP 등록 · MCP 변환, 담당 시스템이 있으면 보임), 구독 · 권한(카탈로그 · 구독 · 승인 · 내 권한), 모니터링, 관리(admin)다. API · MCP를 찾아 사용 신청하는 카탈로그는 구독 · 권한 아래에 있다.

## 2. 시스템 등록 방법

기준정보 › 시스템 화면에서 오른쪽 위 '시스템 등록' 버튼을 누른다. 누구나 등록할 수 있다. 시스템 코드(영문 약어, 시스템 이름도 같은 약어), 구분(업무 시스템 또는 AI Agent), 업무 프로세스, 소속 부서, 데이터 등급, 서비스 URL, 설명을 입력한다. 추가 담당자는 이름이나 이메일로 사용자 목록에서 골라 넣는다. 서버 정보에 호스트명 · IP · 포트 · 환경 · 용도를 넣고 '등록'을 누른다. 등록한 사람이 첫 담당자가 되며 승인 절차는 없다. 'Agent로 채우기'를 누르면 IRP(시스템 마스터)와 DCM(서버 자산)의 정보로 입력란을 채워 준다.

## 3. 시스템 담당자 추가 · 빼기

기준정보 › 시스템에서 시스템을 고르면 담당자 목록이 보인다. 담당자 추가 칸에 이름이나 이메일을 입력해 사용자 목록에서 고르면 바로 담당자가 된다. 승인은 필요 없다. 담당자 이름 옆 X로 뺄 수 있지만 마지막 담당자는 뺄 수 없다. 포탈에 한 번이라도 로그인한 사용자만 목록에 나온다.

## 4. 서버 등록 방법

기준정보 › 서버 화면에서 '서버 추가'를 누른다. 내가 담당하는 시스템을 고르고 호스트명, IP, 포트, 환경(운영 · 검증 · 개발), 용도(WAS · API · MCP 등)를 입력한 뒤 '추가'를 누른다. 'Agent로 채우기'를 누르면 DCM에 있고 아직 포탈에 없는 서버를 찾아 채워 준다. 시스템 등록 양식의 서버 정보도 'Agent로 서버 채우기'로 채울 수 있다.

## 5. API 등록 절차

카탈로그 등록 › API 등록 화면에서 시스템 정보, 기본정보, 업무정보, API 타입(송신 · 수신), 레이아웃, 리소스(메소드 · URL 패턴)를 입력한다. 레이아웃은 엑셀 업로드, Swagger 가져오기, 샘플 JSON으로 채울 수 있다. '저장' 후 '승인 요청'을 누르면 admin이 승인하고 스테이지를 거쳐 운영으로 전환한다. 운영 상태가 된 API만 카탈로그에서 구독할 수 있다.

## 6. MCP 서버 등록 절차

카탈로그 등록 › MCP 등록은 타겟 시스템이 직접 개발한 MCP 서버를 등록하는 화면이다. 전송 방식, 엔드포인트, 인증 방식, 호스트 서버를 입력하고 연결 테스트나 tools/list JSON으로 Tool 목록을 불러온다. Tool마다 공개 여부를 정한다. 저장 → 승인 요청 → admin 승인 → 스테이지 → 운영 순서로 진행한다.

## 7. API를 MCP로 변환하는 방법

카탈로그 등록 › MCP 변환에서 운영 중인 API를 고르면 리소스별로 Tool 이름 · 설명 · 입력 형식이 자동으로 제안된다. 필요한 리소스만 골라 변환하면 A2X가 변환 MCP 서버를 만들고, 승인을 거쳐 운영으로 연다. 변환 MCP 호출은 A2X가 원본 API로 바꿔 전달한다.

## 8. 시스템 구독 신청 방법

카탈로그에서 운영 중인 API나 MCP 서버의 '사용 신청'을 누르면 사용 신청 화면으로 바뀐다. 여러 개를 한 번에 신청하려면 카드의 '담기'(리스트는 체크)로 담고 아래 신청 바의 '한 번에 사용 신청'을 누른다. '시스템 구독 신청' 탭에서 구독할 내 시스템(클라이언트) 하나와 사용 목적을 입력하면 담은 항목이 한꺼번에 신청되고, 항목별 결과(성공 · 실패 사유)가 보인다. 시스템 구독은 클라이언트 시스템 담당자가 신청하고, 대상(프로바이더) 시스템 담당자나 admin이 승인한다. API 연계는 시스템 구독만으로 쓴다.

## 9. Tool 사용 신청 방법

MCP 서버는 시스템 구독이 승인된 뒤 개인 사용자가 Tool별로 사용을 신청한다. 카탈로그에서 MCP 서버의 '사용 신청'(여러 MCP 서버는 담아서 '한 번에 사용 신청') → 'Tool 사용 신청' 탭에서 MCP 서버마다 사용할 Agent 연계와 Tool을 고르고 목적을 한 번 입력한다. 승인은 프로바이더 시스템 담당자나 admin이 한다. 신청 상태는 구독 · 권한 › 내 권한에서 본다. 내 권한은 신청 현황(승인 · 대기 · 취소 · 해지)만 보여 주고, 새 Tool은 카탈로그에서 신청한다. 내 권한의 '더 신청'을 누르면 그 MCP 서버를 담은 사용 신청 화면이 열린다.

## 10. 승인 · 반려 · 해지

구독 · 권한 › 구독 · 승인 화면에 내가 승인할 시스템 구독과 Tool 신청이 모인다. admin에게는 모든 시스템의 승인 대기 신청이 보이고 승인 · 반려할 수 있다(감사 로그에 admin 처리로 남는다). 승인 · 반려 버튼으로 처리하고, 승인된 구독은 해지할 수 있다. 시스템 구독을 해지하면 그 안의 Tool 권한도 함께 해지된다. admin은 같은 화면에서 API · MCP 등록 승인과 운영 전환을 한다.

## 11. 모니터링 보는 방법

모니터링 › API 사용내역 · MCP 사용내역에서 호출을 페이지 단위로 본다. 조회 기간은 오늘 · 24시간 · 7일(기본) · 30일 중 고르거나 '직접 지정'으로 시작 · 종료 날짜와 시간을 넣는다(최대 366일). 성공 · 실패 필터와 검색을 쓸 수 있고, Status를 누르면 호출 흐름과 구간별 응답시간이 팝업으로 보인다. 호출 통계는 일별 · 월별 호출량, 오류율, 평균 응답시간을 보여 준다. 기본은 일별 최근 30일 · 월별 최근 12개월이고, 시작 · 종료 날짜(월별은 월)를 넣으면 그 기간으로 바뀐다. '기본 기간'으로 되돌린다. 일반 사용자는 내 호출, 시스템 담당자는 담당 시스템의 호출을 본다.

## 12. A2X Agent 사용법

오른쪽 위 Agent 버튼으로 채팅을 연다. 연계 방식 상담, 등록 · 구독 양식 채움, 연계 코드 예시, 오류 원인 분석을 한다. /컨설팅 · /채움 · /코드 · /오류로 시작하면 그 Agent로 바로 보낸다. '흐름 보기'로 Agent가 어떤 모듈과 MCP를 거쳤는지 그림으로 본다. Agent는 등록 · 신청을 제출하지 않으며 채운 값은 직접 확인 후 제출한다.

## 13. 컨설팅 문서 관리

관리 › 컨설팅 문서(admin)에서 MD · TXT · DOCX · PDF 문서를 올리면 색인되어 컨설팅 Agent의 답변 근거가 된다. 근거 검색 시험으로 질문에 근거가 잡히는지 확인할 수 있다.

## 14. 등록정보 수정 · 삭제 방법

시스템 정보는 기준정보 › 시스템에서 시스템을 고르고 '정보 수정'을 누른다. 업무 프로세스 · 소속 부서 · 데이터 등급 · 서비스 URL · 설명을 고칠 수 있고 시스템 코드와 구분은 바꿀 수 없다. 서버는 기준정보 › 서버 목록이나 시스템 상세의 서버 정보에서 연필 버튼을 눌러 그 줄에서 고친다. API · MCP 서버는 카탈로그에서 '수정'을 누르면 등록 화면에 저장된 값이 불러와진다. 저장 · 반려 상태는 고친 뒤 저장하거나 승인 요청하고, 승인 대기 중에는 내용만 바뀐다. 이미 승인된(스테이지 · 운영 · 중지) API · MCP를 고치면 '수정 후 재승인 요청'으로 다시 승인 대기가 되며, 재승인과 운영 전환 전까지는 호출할 수 없다. 구독과 Tool 권한은 그대로 유지된다. 사용 신청 내역이 있는 Tool은 뺄 수 없고 비공개로 바꾼다. 변환 MCP는 MCP 변환 화면에서 원본 API로 다시 변환한다. 수정은 그 시스템 담당자와 admin만 할 수 있다. 삭제도 같은 화면에서 한다. 시스템은 상세의 '삭제'(서버 · 담당자 연결도 함께 삭제), API · MCP는 카탈로그 카드의 휴지통 버튼, 서버는 서버 목록의 휴지통 버튼을 누른다. 진행 중(승인 · 대기)인 구독이 있으면 먼저 해지해야 하고, 변환 MCP가 있는 API는 변환 MCP를, API · MCP가 있는 시스템은 그 API · MCP를 먼저 삭제해야 한다. A2X 내장 Agent 시스템은 삭제할 수 없다. 삭제해도 모니터링 호출 로그와 감사 로그는 남는다. 구독 · Tool 신청은 삭제 대신 해지 · 취소한다.

## 15. 인스턴스 모니터링

모니터링 › 인스턴스 모니터링(시스템 담당자 · admin)은 A2X 구성요소가 정상인지 보여 준다. 포탈(웹 프런트엔드 · 포탈 API · DB · 인증 · 감사 로그), MCP 권한 Gateway(권한 판정 · 최근 권한 거부), MCP · API Gateway(A2X MCP 런타임 · 최근 1시간 트래픽 · WSO2), MCP 서버(서버 · 컨테이너별 연결과 최근 호출 오류율), 외부 연계 MCP(마스터 · IRP · DCM), A2X Agent(LLM · 벡터 DB · 임베딩 모델 · 문서 색인), 운영 데이터(호출 로그 수집 · 디스크 · 저장소)를 묶음별로 점검한다. 상태는 정상 · 주의 · 비정상 · 점검 제외이고, 비정상이 있으면 맨 위에 빨간 경보와 해당 구성요소 목록이 나오며 메뉴에 비정상 개수 배지가 붙는다. 15초마다 자동 점검하고 '지금 점검'으로 바로 다시 점검한다. 샘플 주소(.example)인 MCP 서버는 점검 제외로 표시한다. MCP 사용내역에는 Client IP 옆에 실제로 호출한 사용자 ID(로그인 이메일)가 보인다.
